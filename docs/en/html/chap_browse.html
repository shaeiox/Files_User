Chapter 2 — browse.html: The Deep-Link Shell

Landing chapter for the browse.html documentation: the second SPA shell that makes /browse/… routes refresh-proof and shareable.

server.js serves this file for /browse and /browse/… requests. It is the same SPA mounted from a second, path-prefixed shell, so a user who refreshes — or shares — a link like /browse/distributions/ubuntu/ lands in a fully booted application instead of a 404.

🎯 Why read this chapter
It is the frame around every catalogue view: persistent navbar and footer, the asset pipeline in dependency order, and the mount point that router.js fills. Reading it together with index.html shows which chrome is intentionally duplicated per shell and why the two shells must stay in sync.
