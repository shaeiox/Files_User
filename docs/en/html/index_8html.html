Detailed Description

The main SPA shell, boot-loader, and UI skeleton for the CloudAvid File Portal.

📖 Overview: What Does This File Do?

The index.html is the single entry point for the entire CloudAvid File Portal application. It is not a traditional multi-page website; it is a Single Page Application (SPA) where this HTML file acts as an empty "shell" that hosts dynamic content injected by JavaScript.

Primary Responsibilities of this file:

  1. UI Skeleton: Renders the persistent chrome (Navbar, Background Aura, Footer) that stays visible across all views.
  2. Pre-Paint Boot Logic: Executes a critical synchronous script before the browser paints the screen. This prevents "Flash of Unstyled Content" (FOUC) by applying user's saved theme and performance tier immediately.
  3. Mount Point: Provides the <main id="app"> container where the SPA Router (router.js) injects the current view (Home, Browse, etc.).
  4. Asset Orchestration: Loads CSS, Fonts, and JavaScript files in a strictly ordered manner.
Note
This file itself contains minimal logic. All heavy business logic lives inside the deferred JavaScript files loaded at the bottom of <body>.

🏗️ Architectural Flow

The lifecycle of a page load happens in this exact order:

1. Browser downloads index.html

🧩 Block 1: Theme Detection Engine (Pre-Paint)

📍 Location
Inside <head>, in the first inline <script> tag (IIFE - Immediately Invoked Function Expression).
🎯 Purpose
To decide whether the user wants Light Mode or Dark Mode, and apply it to the root HTML element before the browser starts painting. This prevents the annoying "white flash" that occurs when a dark-mode user loads a page that starts as light.
⚙️ How It Works (Step by Step)
  1. Grabs the <html> element reference (document.documentElement).
  2. Sets default theme to 'light'.
  3. Priority #1 — OS Preference: Uses window.matchMedia('(prefers-color-scheme: dark)') to check if the user's operating system is set to dark mode.
  4. Priority #2 — User Choice: Reads localStorage key cav_theme. If the user has manually selected a theme before, this overrides the OS preference.
  5. Apply: Writes the final decision to <html data-theme="dark|light">. CSS variables in tokens.css react to this attribute to color the entire UI.
📥 Inputs
  • OS setting: prefers-color-scheme
  • Browser storage: localStorage.getItem('cav_theme') (values: 'light' or 'dark')
📤 Outputs
  • DOM attribute: <html data-theme="...">
🔗 Dependencies
  • window.matchMedia (Browser API)
  • localStorage (Browser API)
  • Consumed by: tokens.css, theme.js
💻 Actual Code
var root = document.documentElement;
var theme = 'light';
try {
if (window.matchMedia &&
window.matchMedia('(prefers-color-scheme: dark)').matches) {
theme = 'dark';
}
} catch (_) { }
try {
var savedTheme = localStorage.getItem('cav_theme');
if (savedTheme === 'light' || savedTheme === 'dark') {
theme = savedTheme;
}
} catch (_) { }
root.setAttribute('data-theme', theme);
Warning
The try/catch wrapper is crucial. localStorage throws exceptions in Private Browsing mode on some browsers (e.g., Safari), which would crash the entire page without this safety net.

🧩 Block 2: Performance Tier Engine (Pre-Paint)

📍 Location
Same IIFE inside <head>, right after the theme block.
🎯 Purpose
To classify the user's device power (High / Medium / Low / Potato) and apply the corresponding performance mode before rendering. This ensures a slow device does not attempt to render expensive CSS animations and blur effects.
⚙️ How It Works (Step by Step)
  1. Sets default tier to 'medium'.
  2. Accessibility Priority: Checks prefers-reduced-motion. If the user disabled motion at the OS level, we force low tier (no animations).
  3. Read Cache: Reads the cav_perf_tier key from localStorage. This cache was previously written by performance-monitor.js after running device benchmarks.
  4. Parse Cache: Expects a JSON object { tier: 'HIGH', timestamp: 1234567890 }.
  5. Validation: Ensures 4 conditions are met:
    • The tier value is in the whitelist: ['HIGH', 'MEDIUM', 'LOW', 'POTATO']
    • Timestamp is a valid number
    • Cache age is non-negative
    • Cache is less than 7 days old (TTL = 7 * 24 * 60 * 60 * 1000 ms)
  6. Purge: If cache is invalid or expired, delete it (a fresh benchmark will run later).
  7. Apply: Writes to <html data-perf="low|medium|high|potato">.
📥 Inputs
  • OS setting: prefers-reduced-motion
  • Browser storage: localStorage.getItem('cav_perf_tier') (JSON string)
📤 Outputs
  • DOM attribute: <html data-perf="...">
  • Side effect: May purge invalid cache from localStorage
🔗 Dependencies
  • window.matchMedia, localStorage, JSON.parse, Date.now
  • Consumed by: performance-modes.css, performance-monitor.js
💻 Actual Code
var perfTier = 'medium';
var reducedMotion = false;
try {
reducedMotion = window.matchMedia &&
window.matchMedia('(prefers-reduced-motion: reduce)').matches;
} catch (_) { }
if (reducedMotion) {
perfTier = 'low';
} else {
try {
var rawPerf = localStorage.getItem('cav_perf_tier');
if (rawPerf) {
var cachedPerf = JSON.parse(rawPerf);
var cachedTier = String(cachedPerf.tier || '').toUpperCase();
var timestamp = Number(cachedPerf.timestamp);
var cacheTTL = 7 * 24 * 60 * 60 * 1000; // 7 days
var cacheAge = Date.now() - timestamp;
var validTiers = ['HIGH', 'MEDIUM', 'LOW', 'POTATO'];
if (
validTiers.indexOf(cachedTier) !== -1 &&
Number.isFinite(timestamp) &&
cacheAge >= 0 &&
cacheAge < cacheTTL
) {
perfTier = cachedTier.toLowerCase();
} else {
localStorage.removeItem('cav_perf_tier');
}
}
} catch (_) { }
}
root.setAttribute('data-perf', perfTier);
Note
Why cache for 7 days? Running a benchmark on every page load is wasteful. Device performance rarely changes over a week, so we trust the cached value for that period.

🧩 Block 3: Performance Monitor Bootstrap

📍 Location
Standalone <script> tag after the boot IIFE in <head>.
🎯 Purpose
To initialize the PerformanceMonitor module after the DOM is ready.
⚙️ How It Works
  1. Attaches a one-time listener ({ once: true }) to the DOMContentLoaded event.
  2. When DOM parsing finishes, checks if the PerformanceMonitor global exists (it will be loaded by the deferred script performance-monitor.js).
  3. Calls PerformanceMonitor.init({ debug: false }) to start monitoring FPS and device metrics.
📥 Inputs
  • Event: DOMContentLoaded
  • Global: PerformanceMonitor (may or may not exist)
📤 Outputs
  • Side effect: Starts the FPS/performance monitoring loop
💻 Actual Code
document.addEventListener('DOMContentLoaded', function () {
if (typeof PerformanceMonitor !== 'undefined') {
PerformanceMonitor.init({ debug: false });
}
}, { once: true });

🧩 Block 4: Head Assets (Fonts + CSS)

🎯 Purpose
Load external fonts and stylesheets required by the UI.
⚙️ Load Strategy
  • Preconnect: Establishes early connection to Google Fonts CDN to reduce latency.
  • Fonts: Loads 4 font families — Manrope (default UI), Cinzel (headings), Vazirmatn (Persian/Farsi UI), Sora (accent text).
  • CSS Cascade Order (Critical):
    1. tokens.css → Design system variables (colors, spacing)
    2. base.css → Global resets and typography
    3. components.css → Reusable UI parts (buttons, pills, dropdowns)
    4. home.css → Home view specific styles
    5. browse.css → File browser view specific styles
    6. performance-modes.css → Rules driven by [data-perf] attribute

🧩 Block 5: Aura Backdrop (Background Glow)

🎯 Purpose
Creates the ambient glowing background effect visible across the entire application.
⚙️ How It Works
  • Uses 3 stacked absolutely-positioned <div> layers.
  • Each layer has its own CSS radial-gradient and animation.
  • Marked with aria-hidden="true" because it is purely decorative (screen readers skip it).
  • When data-perf="low" or data-perf="potato", animations are disabled by performance-modes.css.
📤 Outputs
  • Visual glow effect on the page background

🧩 Block 6: Navigation Bar (Header)

🎯 Purpose
Provides the persistent top navigation with branding, tabs, and toolbar actions.
🧱 Structural Breakdown

A) Brand Logo (.nav-logo)

  • Wrapped in an anchor with data-link so router.js handles the click as SPA navigation (no full page reload).
  • Image has onerror fallback to hide broken image.

B) Center Tabs (.nav-tabs)

🧩 Block 7: SPA Mount Point

🎯 Purpose
The most important tag in this entire HTML file. It is the empty container where every SPA view (Home, Browse, etc.) gets rendered by router.js.
⚙️ How It Works
  • Starts completely empty when the page loads.
  • router.js reads window.location.pathname and calls the appropriate view renderer (e.g., renderHome() or renderBrowse()).
  • The renderer generates HTML strings and injects them via document.getElementById('app').innerHTML = ....
  • On subsequent navigation, the router clears #app and mounts the next view.
💻 Actual Code
<main id="app"></main>
Warning
Never modify id="app" — it is hardcoded in router.js, home.js, and browse.js.

🧩 Block 8: Deferred Script Pipeline

🎯 Purpose
Loads all business logic modules after HTML parsing finishes (thanks to defer), so page rendering is never blocked.
⚙️ Execution Order (STRICT)
The order matters because later files depend on earlier ones:
# File Role Depends On
1 resource-service.js API layer for backend files/folders —
2 performance-monitor.js Device benchmark + FPS monitor —
3 theme.js Theme toggle logic —
4 i18n.js Translation engine —
5 autocomplete.js Search suggestion widget resource-service
6 home.js Home view renderer resource-service, i18n
7 browse.js Browse view renderer resource-service, i18n
8 router.js SPA router (last!) ALL of the above
Warning
router.js must be last because it immediately triggers the initial route on load, which requires all view renderers and services to already be ready.
