# bulk-download — delta

## MODIFIED Requirements

### Requirement: ZIP download streams a real archive for the selection

The system SHALL provide a server-produced ZIP archive of the selection, generated by streaming real
content. Selected files SHALL be included as files. Selected folders SHALL be included recursively,
with their structure, as directory entries plus the files they contain. Empty folders SHALL be kept.
The archive SHALL NOT be a pre-existing file, SHALL NOT contain placeholder entries, and SHALL be
readable by standard unzip tooling.

#### Scenario: A folder is downloaded as ZIP

- **GIVEN** a folder containing files and a nested empty sub-folder
- **WHEN** the user downloads the folder as ZIP
- **THEN** the archive contains the folder's files under the folder's name, with their real content
- **AND** the empty sub-folder is present as a directory entry

#### Scenario: A selection mixing files and folders

- **GIVEN** one folder and two files are selected
- **WHEN** the user starts the ZIP download
- **THEN** the archive contains the two files and the folder's contents

#### Scenario: A folder and a file inside it are both selected

- **GIVEN** a folder and a file within that folder are both selected
- **WHEN** the archive is produced
- **THEN** the file appears exactly once

## ADDED Requirements

### Requirement: Folder contents are authorized per descendant

When a folder is archived, every descendant SHALL be decided individually with the same access
decision the download endpoint uses. A descendant the caller may not download (hidden, locked,
view-only, unpublished, outside its availability window, or under the legacy release gate without a
session) SHALL be omitted together with everything beneath it. Hidden-name entries and symbolic
links SHALL never be included. A selected folder that is itself refused SHALL refuse the request,
exactly as a refused selected file does.

#### Scenario: A locked file inside a downloaded folder

- **GIVEN** an open folder containing a file locked by admin policy
- **WHEN** an anonymous user downloads the folder as ZIP
- **THEN** the archive is produced
- **AND** it does not contain the locked file

#### Scenario: A hidden sub-folder inside a downloaded folder

- **GIVEN** an open folder containing an unpublished sub-folder
- **WHEN** the folder is downloaded as ZIP
- **THEN** neither the sub-folder's name nor its contents appear in the archive

#### Scenario: The selected folder is locked

- **GIVEN** a folder locked by admin policy
- **WHEN** an anonymous user requests it as ZIP
- **THEN** the request is refused with an authentication error

### Requirement: Folder archives respect the classic-ZIP ceilings

Expansion SHALL stop and the request SHALL be refused with `413` as soon as the expanded selection
exceeds 65 535 entries or 4 GiB. A truncated archive SHALL NOT be produced.

### Requirement: Every folder offers a ZIP download

Each downloadable folder row and the folder inspector card SHALL offer a "Download folder as ZIP"
control. A single-folder archive SHALL be named after the folder.

### Requirement: Shift selects a range

Shift + click on a row or its checkbox SHALL set every visible row between the anchor (the last row
toggled without Shift) and the clicked row to the anchor's state. Rows outside the range SHALL keep
the state they had before the Shift run started. Consecutive Shift-clicks SHALL replace the previous
range, not add to it.

#### Scenario: Shift-click after a click

- **GIVEN** row 2 was clicked and is selected
- **WHEN** the user Shift-clicks row 7
- **THEN** rows 2–7 are selected

#### Scenario: Shift-click toward the anchor shrinks the range

- **GIVEN** rows 2–7 were selected by a Shift-click from anchor row 2
- **WHEN** the user Shift-clicks row 4
- **THEN** rows 2–4 are selected and rows 5–7 are not

### Requirement: Dragging selects the rows it crosses

Pressing the primary mouse button on a row's inert area or on empty table space and dragging SHALL
draw a selection band and select every visible row the band touches, live, while keeping rows
selected before the drag. A drag that starts on a selected row SHALL deselect instead. Releasing the
button SHALL NOT also toggle the start row. Movement under the drag threshold SHALL behave as a
click. Near the top or bottom edge the list SHALL auto-scroll. Esc during a drag SHALL restore the
selection from before the drag. Touch input SHALL keep scrolling.

### Requirement: Selection is keyboard-operable

While focus is inside the file table: Space SHALL toggle the focused row, Shift + ↑/↓ SHALL move focus
and extend the range from the anchor, Ctrl/Cmd + A SHALL select every visible row, and Esc SHALL
clear the selection.
